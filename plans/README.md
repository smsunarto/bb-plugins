## Findings considered and rejected

- **Chart labels use fixed `text-sm` / `text-xs` while prose is em-scaled**
  (`plugins/canvas/src/app/charts.tsx:113,117,131,525,558,575,591,617`): the
  two styles differ by 1px of body size (17px default, 16px github), so the
  mismatch is at most 1px. The SVG `fontSize={10}` values (lines 176, 258) are
  viewBox user units and already scale with the chart width. Not worth a change.
- **`.canvas-diff` pins the diffs.com palette instead of the bb theme**
  (`plugins/canvas/src/app/app.css:297-313`): the comment above the rule records
  this as a deliberate choice (Pierre should look like diffs.com, and beat theme
  overrides such as Monokai). By design. Only the frame border hex is inconsistent
  and that is folded into plan 001.
- **Block rhythm after the per-paragraph markdown split**: measured in the live
  dev instance (dark theme, flaky-test-triage example). Every gap between
  top-level blocks is 28px (one 36px between two component blocks). Consistent.
  Nothing to fix.
- **Comment "+" button can touch the pane edge in narrow panels**
  (`plugins/canvas/src/app/app.css:385` `right: -1.5rem`, prose padding
  `clamp(24px, 4cqw, 56px)`): at a 703px pane the button's right edge sits 5.6px
  inside the scroll container. Below 600px it sits exactly on the edge, so only
  the focus ring clips. Cosmetic and rare. Revisit if comments get a gutter.
- **`"SN Pro"` is hard-coded first in the prose font stack**
  (`plugins/canvas/src/app/app.css:24`), ahead of the host `--font-sans`. Neither
  README nor SKILL.md mentions it. This is a product decision (keep and document,
  or drop so the canvas follows the host font), not an engineering plan. Owner
  to decide.
- **github style overrides host tokens inside the canvas** (`styles/github.css`):
  documented intent in the github-style example ("the page is white on every bb
  theme"). By design.
- **github tables render `display:block; width:max-content`**: matches
  github.com. By design.
