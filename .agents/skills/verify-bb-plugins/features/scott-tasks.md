# Tasks

Tasks (`scott-tasks`) is a Linear-style tracker inside bb. A **Tasks** nav panel lists tracker projects, folders, and agent presets in the left sidebar. The main pane shows list and board views, a detail page per task (`VER-1`-style keys), and a Manage page for labels, presets, and folders. Tasks link to bb threads, which show up as cards on the task, as a **Tasks** section in the thread's Info, and as a **Task** side-panel tab. `bb tasks …` covers every record from the CLI, an `@` mention provider sends a task to an agent as context, and a `::task{key="…"}` directive renders a task card in agent messages.

## Sub-features

- `tasks-nav` opens the **Tasks** nav panel. bb's nav entry shows an open-task count badge (accessible name `Tasks, N open tasks`), and the panel replaces the left sidebar with `Back to app`, a `Workspace` group (`All tasks`, `Active`, `Backlog`), a `Projects` group with project rows, folders, and `New project` (shown once a project exists), `Agent presets`, `New preset`, and `Manage`.
- `tasks-first-run` shows `No projects yet` with a **New project** button when no tracker project exists.
- `tasks-project-ui` creates a project from the **New project** dialog (Name, Prefix, Color, Folder, Linked bb project) and opens it.
- `tasks-project-cli` covers `bb tasks project create|list|show|update`, including `--rename-prefix`, `--link-bb-project`, and `--unlink-bb-project`.
- `tasks-folders` covers folders: `bb tasks folder create|list|update|delete`, **Manage → Folders** (rename, parent, delete), collapsible folder groups in the sidebar, and inline **New folder…** in the New project dialog.
- `tasks-new-task` creates a task from the **New task** dialog. It opens from the `C` key, the topbar **New task** button, or a status group's `New <Status> task` button. It has Project, Status, Priority, Labels, Due date, **Create more**, **Discard draft**, a draft that survives closing, and opens the new task when done.
- `tasks-list` groups rows by status with collapsible headers, a **Filter** toggle that reveals Status/Priority/Label filters with **Clear**, a `Sort: <order>` menu, a task count, and `J`/`K`/arrow/`Enter` row navigation. Filters and sort are saved per scope.
- `tasks-row-edit` edits a row in place: `S`, `P`, and `L` open the status, priority, and label menus on a focused row, and a right-click opens the context menu with **Status**, **Priority**, **Due date**, **Labels**, and **Move to project**.
- `tasks-bulk` toggles row selection with `X` or `Select VER-n` and applies **Set status** to every selected row, with **Clear selection** to drop them.
- `tasks-board` switches between **List** and **Board** (remembered per project). The board shows Backlog to Done columns, plus Canceled only when non-empty, and supports pointer drag between and within columns and a `New <Status> task` button per column.
- `tasks-detail` is the task page: an editable title, the Properties rail (status, priority, due date, project, labels, dispatch target, dispatch control), a description editor, **Add sub-task**, the `n / total` pager with **Previous task** and **Next task**, and **Back (Esc)**.
- `tasks-comments` is the Activity section: the comment composer, the **Comment** button, the agent-notification toggle, and system comments.
- `tasks-attachments` covers files on the task (**Attach file** on the detail page and in the composer, **Attach files** in New task) and `bb tasks attachment add|list|get|remove`.
- `tasks-labels` covers labels: **Manage → Labels** (add, edit, delete with a usage warning), creating a label inline from the label pickers, and `bb tasks label create|list|delete`.
- `tasks-presets` covers presets: **New preset** in the sidebar, **Manage → Presets** (edit and delete), the **Add a preset…** button on a task with no presets, and `bb tasks preset list|show|create|update|delete`.
- `tasks-dispatch-target` links or unlinks a bb project from the task rail's **Edit dispatch target** menu.
- `tasks-delegate` starts a worker thread from the rail's dispatch button or **Choose dispatch preset** (`A`), or with `bb tasks delegate|dispatch`. It moves a backlog/todo task to `in_progress`.
- `tasks-thread-links` covers `bb tasks attach|detach|threads`, the **Agent threads** section on a task (`N working now`, **Open thread**, `Detach <title>` with a **Detach thread?** confirmation), and live status labels (Starting, Working, Idle, Completed, Failed, Archived).
- `tasks-pr-pill` shows the pull request a linked thread opened (`Pull request #N: <state>`, with **Open on GitHub**) on its thread card, or `PR unavailable` when the PR can't be read. It needs the Source Control plugin and a GitHub PR.
- `tasks-thread-info` adds a **Tasks** section to a linked thread's Info. Selecting a row opens the **Task** side-panel tab.
- `tasks-task-tab` is the **Task** thread side-panel tab. It shows the full detail view, has an `Open VER-n in Tasks` button, and adapts to the panel's size.
- `tasks-directive` renders `::task{key="VER-1"}` in an agent message as a live card. Clicking it opens the Task tab, and `Open VER-1 in Tasks` opens the page. It also has not-found, loading, and invalid-key states.
- `tasks-mentions` adds a **Tasks** provider to the bb composer's `@` menu. Inside task descriptions and comments, `@` inserts a task pill.
- `tasks-move` moves a task and its sub-tasks to another project, from `bb tasks move`, the rail's **Move to project**, or the row context menu. The task gets a new key and the old key keeps resolving.
- `tasks-active` is the `Active` view, which lists tasks with a working (or starting) agent thread. When none are working it shows `No agents working right now`.
- `tasks-parent-notify` covers `bb tasks comment --notify-parent` from a child thread (it wakes the parent) and `--notify` (it delivers to the latest responding agent).
- `tasks-cli-contract` covers `bb tasks status`, `--help` at every level, the `--json` failure envelope, and `seed-demo --yes`.
- `tasks-skill` is the bundled `tasks` agent skill.
- `tasks-thread-pills` lists threads as well as tasks when you type `@` in a task description or comment, and inserts a thread pill. <!-- unverified: added from a source audit, not driven -->
- `tasks-parent-notify-retry` redelivers a failed `--notify-parent` wake with backoff (1, 2, 5, then 15 minutes), up to six attempts, then marks it undeliverable. <!-- unverified: added from a source audit, not driven -->
- `tasks-crew-rpc` serves custom task fields and crew snapshots (`defineField`, `setField`, `taskFields`, `crewSnapshot`) to Captain's `verdict` and Overview; see [Captain](captain.md). <!-- unverified: added from a source audit, not driven -->
- `tasks-page-frame` draws the Tasks page edge to edge at widths of 768px and up, without bb's inset frame and rounded corners. <!-- unverified: added from a source audit, not driven -->

## How to get to it (user POV)

- Choose **Tasks** in bb's left navigation (`[data-sidebar-navigation-item="scott-tasks/tasks"]`). The panel's route is `$URL/plugins/scott-tasks/tasks/<sub>`, where `<sub>` is `all`, `active`, `manage`, `task/<KEY>`, or `<tracker-project-id>`.
- In the Tasks sidebar, choose `All tasks`, `Active`, `Backlog`, a project row, a folder header, `New project`, a preset row, `New preset`, or `Manage`. The topbar's `Task views` nav repeats `All`, `Active`, and `Backlog`.
- On any Tasks page except a task or Manage, press `C` or choose **New task**.
- In a list, focus a row and press `Enter`, `S`, `P`, `L`, or `X`. Right-click a row, or focus it and press `Shift+F10`, for the context menu. <!-- unverified: Shift+F10 sent by agent-browser does not open it (headless limit) -->
- On a task page, press `S`, `P`, `L`, or `A` to open the status, priority, labels, or dispatch menu. Press `Escape` (or **Back (Esc)**) to go back.
- In a thread linked to a task, open the thread's Info (the right panel's `Show thread info panel` button) and choose a row under **Tasks**. Or choose a task card in an agent message. The right panel's `New tab` → **Task** opens an empty Task tab.
- In the bb composer, type `@` and a task key or title; a **Tasks** group lists matching tasks.
- Use `bb tasks …`. `bb tasks --help` lists every command.
- Tasks has no plugin settings. `$URL/settings/plugins/scott-tasks` shows only bb's `Plugin details` page, and `"$TB" plugin config scott-tasks --json` prints an empty `schema`.

## Driving it with agent-browser

Preconditions:

- The doctor passes with `--plugin scott-tasks`.
- No bb built-in plugin competes for `bb tasks` on bb 0.50.1: `"$TB" plugin list --json | jq -r '.plugins[] | select(.id=="tasks" or .id=="scott-tasks") | "\(.id) \(.enabled)"'` prints only `scott-tasks true`.
- Tasks data lives in the instance's own plugin database. Live's tasks are not mirrored, so the instance starts with no tracker projects. The instance is shared: check `"$TB" tasks project list --json` prints `{"projects":[]}` before the first-run drive, and delete every tracker project you create (see **Cleanup**) so the next run sees first-run again.
- Create a bb project and an idle thread, and record the printed ids. Tracker fixtures come later, because the first-run drives need zero tracker projects.

  ```bash
  FX="$BB_THREAD_STORAGE/verify/$RUN-fixtures"; mkdir -p "$FX"
  git init -q "$FX/verify-tasks" && git -C "$FX/verify-tasks" commit -q --allow-empty -m init
  "$TB" project create --name verify-tasks --root "$FX/verify-tasks" --json | jq -r '.project.id // .id'   # <bb-project-id>
  AT=$(date -u -d '+7 days' +%Y-%m-%dT%H:%M:%SZ)   # macOS: date -u -v+7d +%Y-%m-%dT%H:%M:%SZ
  "$TB" thread spawn --project <bb-project-id> --title "Tasks fixture thread" --prompt hello --send-at "$AT" --json | jq -r '.thread.id // .id'   # <thread-id>
  ```

  The `--send-at` a week out keeps the thread without an agent turn; bb reports it `pending` with one queued message.

- **First run (`tasks-first-run`).** With no tracker project, run `agent-browser --session "$RUN" open "$URL/plugins/scott-tasks/tasks/all"` and `agent-browser --session "$RUN" wait --text "No projects yet" --timeout 15000`. The page shows `Create a project to start tracking tasks and dispatching work to agents.` and a **New project** button. The sidebar shows `All tasks 0`, `Active 0`, `Backlog`, `No presets yet.`, `New preset`, and `Manage`, with no `Projects` group yet.
- **Create a project in the UI (`tasks-project-ui`).** Run `agent-browser --session "$RUN" find role button click --name "New project"` and `agent-browser --session "$RUN" wait --text "Projects group tasks under a shared key prefix."`. The dialog has textboxes `Name` and `Prefix`, a `Color` radiogroup, comboboxes `Folder` (`No folder`) and `Linked bb project` (`Not linked`), and a disabled `Create project`. Type the name with `agent-browser --session "$RUN" find label "Name" fill "verify-ui"`. Prefix fills itself with a derived value. Overwrite it with `agent-browser --session "$RUN" find label "Prefix" fill "VUI"`, then run `agent-browser --session "$RUN" find role button click --name "Create project"`. The dialog closes, the URL becomes `…/tasks/<id>`, the topbar reads `verify-ui`, and the body shows `No tasks yet`. The sidebar gains `Projects` with `verify-ui 0` and `New project`. Confirm with `"$TB" tasks project list --json | jq -r '.projects[] | "\(.prefix) \(.name)"'`, which lists `VUI verify-ui`.
- **Tracker fixtures and project CLI (`tasks-project-cli`).** Create the tracker fixtures and record the ids. Tasks created from the CLI start in `backlog`.

  ```bash
  "$TB" tasks project create --name verify-tracker --prefix VER --json | jq -r .project.id      # <ver-id>
  "$TB" tasks project create --name verify-other --prefix VERB --json | jq -r .project.id       # <verb-id>
  "$TB" tasks label create --project VER --name verify-label --json
  "$TB" tasks create --project VER --title "Verify task one" --priority high --label verify-label --json | jq -r '.task.key, .task.status'   # VER-1 backlog
  "$TB" tasks create --project VER --title "Verify task two" --json | jq -r .task.key        # VER-2
  "$TB" tasks create --project VUI --title "VUI task" --json | jq -r .task.key               # VUI-1
  ```

  - `"$TB" tasks project list` prints a table with columns `PREFIX  NAME  FOLDER  BB PROJECT  ID` and the `VER`, `VERB`, and `VUI` rows.
  - `"$TB" tasks project show VER --json | jq -r .project.name` prints `verify-tracker`.
  - `"$TB" tasks project update VUI --name verify-ui-renamed --json | jq -r .project.name` prints `verify-ui-renamed`, and the sidebar row follows without a reload.
  - `"$TB" tasks project update VUI --rename-prefix VUX --json | jq -r .project.prefix` prints `VUX`, and `"$TB" tasks list --project VUX --json | jq -r '.tasks[].key'` prints `VUX-1`.
  - `"$TB" tasks project update VER --link-bb-project <bb-project-id> --json | jq -r .project.linkedBbProjectId` prints `<bb-project-id>`; `--unlink-bb-project` prints `null`.

- **CLI update and list (`tasks-project-cli`, `tasks-list`).**
  - `"$TB" tasks update VER-2 --status todo --priority medium --due 2030-01-01 --json | jq -r '.task.status, .task.priority, .task.dueDate'` prints `todo`, `medium`, and `2030-01-01`.
  - `"$TB" tasks update VER-2 --no-due --add-label verify-label --json | jq '.task.dueDate, (.task.labelIds | length)'` prints `null` and `1`.
  - Return VER-2 to `backlog` and drop the label with `"$TB" tasks update VER-2 --status backlog --remove-label verify-label`.
  - `"$TB" tasks list --project VER --status backlog --json | jq -r '.tasks[].key'` lists both tasks, and `"$TB" tasks list --search "task one" --json | jq -r '.tasks[].key'` prints `VER-1`.

## Gotchas

- Neither the UI nor the CLI can delete a task or a tracker project. Only the `deleteTask` and `deleteProject` plugin RPCs can; `"$TB" plugin rpc list scott-tasks` prints `No discoverable RPC methods.`, but `plugin rpc call` works. Pass `"force":true` to delete a project that still has tasks.
- `Escape` with no menu, dialog, or input open navigates back in history, out of Tasks if you arrived from elsewhere. Menus close by themselves after a pick, and the title commits and blurs on `Enter`, so a habitual extra `Escape` leaves the page. A following `c` or `p` then types into Home's autofocused composer; check and clear that draft.
- `C`, `S`, `P`, `L`, `A`, `X`, `J`, and `K` are ignored while focus is in an input, a contenteditable, or an open menu or dialog.
- On the all-tasks route the New task dialog defaults to the first project by name, not the one you expect. Pick `Project` explicitly.
- The New task draft survives closing the dialog and a page reload. Discard it before evidence so a later run does not start prefilled.
- The view toggle writes the view into the plugin path, URL-encoded (`…/<id>%3Fview%3Dboard`). A real query `…/<id>?view=board` is ignored and the saved view wins.
- The list and board are pointer-only for drag. A touch pointer does not start a drag. The board ignores drags under 5 px, and a drag that ends outside the board snaps back.
- Right-click needs `mouse down right` / `mouse up right`; agent-browser's `Shift+F10` does not open the context menu, and `click --button right` left-clicks.
- Settings pages replace the Tasks sidebar too. Return to `$URL/plugins/scott-tasks/tasks/all` before asserting on it.
- `--project` takes a tracker prefix such as `VER`, never a bb `proj_…` id.
- A `--send-at` scheduled thread attached to a task reads `Starting` (`liveStatus: starting`), counts toward `N working now`, the sidebar's `Active` count, and `tasks list --active`. `Idle`, `Working`, and `Completed` need a thread that has run.
- Saving the **Edit preset** dialog replaces a model id the provider does not list with the provider's default: a CLI preset made with `claude-sonnet-4-5` saved as `claude-opus-5-5`. Re-read `preset show` after any UI save.
- bb's thread Info shows `No thread details available.` for a thread with no turn (a `--send-at` fixture), so the `Tasks` Info section needs a thread with one fake-agent turn.
- Remove your fake-agent entry from `provider-acp` `customAgents` at the end (SKILL.md **Free agent turns**).
- The instance is shared with other verifiers; a page can end up on another thread mid-drive (cause not confirmed). Re-check `get url` before an assertion that fails unexpectedly.
