# GTD Sidebar

GTD Sidebar replaces bb's thread list with an inbox: threads sit on shelves by who can act next, split into project groups once two projects are in view, and leave the list through snooze or settle. Each row carries a status-or-age slot, a hover card, a shared context menu (a long-press sheet on a phone), and family nesting; a `bb gtd-sidebar` CLI renames threads and edits layout preferences, and an opt-in setting has each root thread's agent name its own thread.

## Sub-features

- `gtd-shelves` places idle threads under `Next Action`, working threads under `Waiting`, and parked ones under `Snoozed` and `Settled`.
- `gtd-groups` splits a shelf into project groups when two or more projects are in view.
- `gtd-group-fold` folds and unfolds a project group from its header.
- `gtd-snooze` hides a thread until 09:00 tomorrow under a counted `Snoozed` shelf.
- `gtd-settle` archives a thread and moves it to `Settled`.
- `gtd-grouping-setting` turns project groups off and on from the plugin settings.
- `gtd-sidebar-choice` registers `GTD Sidebar (inbox)` as a sidebar thread list, with `No threads yet`, `No threads found`, and `Could not load threads.` empty states.
- `gtd-pinned-shelf` lists pinned threads on an unfoldable `Pinned` shelf above `Next Action`.
- `gtd-waiting-shelf` lists working threads on a `Waiting` shelf that starts open and folds to `Waiting (n)`; their Snooze is disabled.
- `gtd-slopcop-shelf` collects SlopCop-originated reviews on a `SlopCop` shelf that starts folded.
- `gtd-snooze-toast` confirms a snooze with `Snoozed until tomorrow, <time>` and an `Undo` action.
- `gtd-snoozed-shelf` expands `Snoozed (n)` to slim rows showing the time left until wake, each with `Wake now`.
- `gtd-settled-shelf` expands `Settled (n)` to the last 24 hours of archives, project groups folded, each row with `Un-settle`.
- `gtd-settle-undo` restores a settled thread from bb's `Archived <title>` toast.
- `gtd-settle-advance` opens the next row in the same shelf when the open thread is settled.
- `gtd-settle-palette` adds `GTD Sidebar: settle thread` to bb's command palette.
- `gtd-row-menu` opens one right-click / `Shift+F10` menu per row: GTD moves first, then every bb and plugin thread action except Archive.
- `gtd-rename-inline` renames a row in place from the menu's `Rename` or a double-click.
- `gtd-group-reorder` reorders projects in bb from the group header's `Move up` / `Move down` or by dragging a header.
- `gtd-group-new-thread` opens the composer for a project from the header's `New thread in <project>` button.
- `gtd-group-captain` opens the `New Captain` dialog from the header's `New Captain directing <project>` button while the Captain plugin runs.
- `gtd-status-slot` shows a status glyph, unread dot, shortcut pill, or age in each row's trailing slot.
- `gtd-unread` draws an unread title at medium weight with an `Unread response` description.
- `gtd-hover-card` shows a row's title, project, branch, remote machine, family relation, and agent provider.
- `gtd-families` nests children under a parent with a persisted fold, keyboard tree navigation, family snooze, and drag nest/un-nest.
- `gtd-machine-globe` leads a remote thread's title with an `On <machine>` globe, governed by the **Local machine** setting.
- `gtd-scope` follows bb's own project scope; the plugin registers no scope or machine picker of its own.
- `gtd-compact-layout` gives a phone-width window taller rows, a long-press action sheet, the `New thread` pill, header `New thread` and `Settle` buttons, and a drawer that dismisses the keyboard.
- `gtd-haptics-setting` adds iOS haptic switches to the long-press sheet when **Enable mobile haptics** is on.
- `gtd-gitbutler-setting` replaces a primary checkout's branch label with GitButler's when **Show GitButler branches** is on.
- `gtd-naming-setting` gives each root thread's agent rename instructions, with the project's `.agents/GTD_NAMING.md` rules, when **Let agents name threads** is on.
- `gtd-naming-skill` ships the user-invoked `configure-gtd-naming` skill.
- `gtd-rename-cli` renames a thread with `bb gtd-sidebar rename [<threadId>] [--title <title>]`.
- `gtd-prefs-cli` lists, reads, writes, and resets layout preferences with `bb gtd-sidebar prefs list|get|set|reset`.
- `gtd-keyboard` drives rows by keyboard: `Tab` to park buttons, `Shift+F10` menus, arrow keys through families, and bb's thread jump keys.
- `gtd-capy-navigation` registers `GTD Sidebar (Capy list)` as an alternative sidebar navigation.
- `gtd-search` opens every shelf and group while bb's sidebar search has a query.
- `gtd-captain-rows` keeps Captain threads open: Settle and Snooze stay disabled, the row leads with the Captain icon, and a `Needs you` count shows.
- `gtd-row-badges` draws other plugins' row badges as chips after the title.
- `gtd-legacy-cleanup` deletes the 0.4.x `gtd-sidebar:v1:*` web-storage keys on load.
- `gtd-rpc` exposes discoverable `snooze`, `unsnooze`, and `listLifecycle` RPC methods (`"$TB" plugin rpc call gtd-sidebar …`), refusing threads that must stay open. `"$TB" plugin rpc list gtd-sidebar` lists them, and `listLifecycle` with `{}` returns `{"rows": []}` when nothing is snoozed. Snoozing through the RPC is not driven. <!-- unverified -->
- `gtd-hidden-workers` keeps a thread on `Waiting` with a `background agents` count while its hidden Review or Arena workers run. <!-- unverified: added from a source audit, not driven -->
- `gtd-pending-row` shows an inert, shimmering `Waiting` placeholder for a thread just sent from Home until bb lists it. <!-- unverified: added from a source audit, not driven -->
- `gtd-boat-glyph` leads a thread on a Boat sandbox machine with a muted bot glyph instead of the globe. Needs a Boat machine. <!-- unverified: added from a source audit, not driven -->
- `gtd-delete-cleanup` drops a deleted thread's snooze and fold state. <!-- unverified: added from a source audit, not driven -->

## How to get to it (user POV)

- Installing the plugin makes it the sidebar. **Settings → Appearance → Sidebar thread list** lists `GTD Sidebar (inbox)`.
- Hover a row on a pointer device to reveal **Snooze until tomorrow** and **Settle**. On touch, or from the keyboard, focus the row link and press `Tab`.
- Right-click a row, or focus it and press `Shift+F10`, for its context menu.
- Open **Settings → Plugins → GTD Sidebar** for **Group threads by project**.
- The same settings page holds **Local machine**, **Let agents name threads**, **Enable mobile haptics**, and **Show GitButler branches**.
- Choose a folded shelf header (`Waiting`, `SlopCop`, `Snoozed (n)`, `Settled (n)`) to open or close it. On a parked row, hover or `Tab` from its link to reach **Wake now** or **Un-settle**.
- Right-click a project group header, or focus it and press `Shift+F10`, for **Move up** and **Move down**; drag a header onto another group on desktop. The header's `+` is **New thread in <project>**; with Captain running, an anchor beside it is **New Captain directing <project>**.
- Choose a family's chevron (**Expand children of <title>** / **Collapse children of <title>**), or press `ArrowRight` / `ArrowLeft` on the parent row.
- Rest the pointer on a row, or reach it with `Tab`, for its hover card.
- Double-click a row's title, or choose **Rename** in its menu, to rename it in place.
- On an open thread, bb's command palette lists **GTD Sidebar: settle thread**.
- In a window under 768px wide, hold a row for its action sheet, use the floating **New** pill for a new thread, and use the thread header's **New thread** and **Settle** buttons.
- In a terminal: `bb gtd-sidebar rename …` and `bb gtd-sidebar prefs …`.
- **Settings → Appearance → Sidebar navigation** lists `Automatic` (which chooses `GTD Sidebar (Capy list) (gtd-sidebar)`) and `GTD Sidebar (Capy list)`. With the plugin installed, the rows above the inbox (`New thread`, `Source Control`, …, `More`) are already the Capy list.
- The agent-text files and the `configure-gtd-naming` skill appear under **Agent instructions → Plugin prompts → GTD Sidebar** when the Agent Instructions plugin is enabled. The Capy list's `Agent instructions` row opens it at `/plugins/agent-instructions/instructions`.

## Driving it with agent-browser

Preconditions:

- The doctor passes with `--plugin gtd-sidebar`.
- Two fixture projects with idle threads exist. Create them, and record the printed project and thread ids:

  ```bash
  FX="$BB_THREAD_STORAGE/verify/$RUN-fixtures"; mkdir -p "$FX"
  for n in alpha beta; do git init -q "$FX/verify-$n" && git -C "$FX/verify-$n" commit -q --allow-empty -m init
    "$TB" project create --name "verify-$n" --root "$FX/verify-$n" --json | jq -r '.project.id // .id'; done
  AT=$(date -u -d '+7 days' +%Y-%m-%dT%H:%M:%SZ)   # macOS: date -u -v+7d +%Y-%m-%dT%H:%M:%SZ
  "$TB" thread spawn --project <alpha-id> --title "Alpha fixture one" --prompt hello --send-at "$AT" --json | jq -r '.thread.id // .id'
  "$TB" thread spawn --project <alpha-id> --title "Alpha fixture two" --prompt hello --send-at "$AT" --json | jq -r '.thread.id // .id'
  "$TB" thread spawn --project <beta-id> --title "Beta fixture one" --prompt hello --send-at "$AT" --json | jq -r '.thread.id // .id'
  ```

  A `--send-at` a week out keeps each thread idle with no agent turn.

- Record the mirrored settings before changing any: `"$TB" plugin config gtd-sidebar --json | jq .values > "$EV/gtd-settings-before.json"`. Restore each changed key to this value at the end.
- The extended steps after **Settle** add fixtures as they need them, with the same `thread spawn … --send-at "$AT"` line. Record each id.
- Steps that need a finished, running, or failed turn (age label, unread, Waiting, families, thread namer, self-rename guard) use the free fake agent: register `acp-verify-fake` as SKILL.md **Free agent turns** describes, and spawn with `--provider acp-verify-fake --title "<title>"`. Always pass `--title`.

- **Shelves and groups.** Open the app and wait for the fixtures. Run `agent-browser --session "$RUN" open "$URL"`, `agent-browser --session "$RUN" wait --text "Alpha fixture one" --timeout 15000`, and `agent-browser --session "$RUN" snapshot -i -c -s '[data-gtd-sidebar-thread-list]'`. The snapshot has region `Next Action`, buttons `verify-alpha project` and `verify-beta project`, and each fixture link under its project.
- **Fold a group.** Choose the alpha header. Run `agent-browser --session "$RUN" find role button click --name "verify-alpha project"`. The header reports `expanded=false`, its name becomes `verify-alpha project, 2 threads`, and the alpha links leave the snapshot. Choose it again to unfold; `find role button` matches the longer name by substring.
- **Grouping setting.** Run this before snooze and settle, while both projects have rows in `Next Action`. Open the setting with `agent-browser --session "$RUN" open "$URL/settings/plugins/gtd-sidebar"` and `agent-browser --session "$RUN" wait --text "Group threads by project"`, then run `agent-browser --session "$RUN" find role switch click --name "Group threads by project"`. The switch reports `checked=false`, and `"$TB" plugin config gtd-sidebar --json | jq .values.groupThreadsByProject` prints `false`. Return with `agent-browser --session "$RUN" open "$URL"` and `agent-browser --session "$RUN" wait --text "Alpha fixture one"`. The sidebar snapshot lists every fixture link under `Next Action` with no `verify-… project` buttons. Choose the switch again and return Home: both headers are back.
- **Snooze.** Focus the row link, tab to its first park button, and press Enter. Run `agent-browser --session "$RUN" focus '[data-gtd-row="<alpha-one-id>"] a[data-sidebar-thread-id]'`, `agent-browser --session "$RUN" press Tab`, and `agent-browser --session "$RUN" eval 'document.activeElement.getAttribute("aria-label")'`, which returns `"Snooze until tomorrow"`. Then run `agent-browser --session "$RUN" press Enter` and `agent-browser --session "$RUN" wait --text "Snoozed"`. A `Snoozed (1)` shelf appears and `Alpha fixture one` leaves `Next Action`.
- **Snooze persists.** Reload with `agent-browser --session "$RUN" open "$URL"` and `agent-browser --session "$RUN" wait --text "Snoozed (1)"`. The shelf and count remain.
- **Settle.** On `Alpha fixture two`, focus the row link as in Snooze and press `Tab` twice; the active label is `"Settle"`. Press `Enter` and run `agent-browser --session "$RUN" wait --text "Settled"`. An `Archived Alpha fixture two` toast with an undo button appears, and a `Settled (1)` shelf replaces the row. Confirm the stored change with `"$TB" thread show <alpha-two-id> --json | jq .thread.archivedAt`, which prints a timestamp, not `null`.

- **Snoozed shelf and Wake now (`gtd-snoozed-shelf`).** Open the shelf with `agent-browser --session "$RUN" find role button click --name "Snoozed"`; the header reports `expanded=true` and its label drops the count. Run `agent-browser --session "$RUN" snapshot -i -c -s 'section[aria-label="Snoozed"]'`: it holds a `verify-alpha project` header (open) and the `Alpha fixture one` link. Read the wake label with `agent-browser --session "$RUN" get text '[data-gtd-row="<alpha-one-id>"]'`; it ends in the hours left until 09:00 tomorrow, such as `14h`. Focus the link as in Snooze, `press Tab`, and the active label is `"Wake now"`. Press `Enter`: `Alpha fixture one` returns under `Next Action` and the `Snoozed` shelf disappears. Reload with `open "$URL"` and `wait --text "Alpha fixture one"`; no `Snoozed` shelf renders.
- **Settled shelf and Un-settle (`gtd-settled-shelf`).** Run `agent-browser --session "$RUN" find role button click --name "Settled"`. Snapshot `-s 'section[aria-label="Settled"]'`: its group header reads `verify-alpha project, 1 thread` with `expanded=false`, because Settled groups start folded. Click that header by its `@ref` from the scoped snapshot; `Alpha fixture two` appears. Focus its link, `press Tab`, and the active label is `"Un-settle"`. Press `Enter`. The row returns under `Next Action`, the `Settled` shelf disappears, and `"$TB" thread show <alpha-two-id> --json | jq .thread.archivedAt` prints `null`.
- **Snooze toast and Undo (`gtd-snooze-toast`).** Snooze `Alpha fixture one` again by the Tab path. Run `agent-browser --session "$RUN" wait --text "Snoozed until" --timeout 5000`; the toast reads `Snoozed until tomorrow, 9:00 AM` (time in the browser's locale). Run `agent-browser --session "$RUN" find role button click --name "Undo"`. The row returns under `Next Action` and no `Snoozed` shelf renders after a reload (`eval '!!document.querySelector("section[aria-label=Snoozed]")'` returns `false`). Read the toast with `eval '[...document.querySelectorAll("[data-sonner-toast]")].map(t=>t.innerText).join(" | ")'`, which returns `"Snoozed until tomorrow, 9:00 AM\nUndo"`.
- **Settle undo (`gtd-settle-undo`).** Settle `Alpha fixture two` again by the Tab path, wait for `Settled`, then run `agent-browser --session "$RUN" find role button click --name "Undo"` on the `Archived Alpha fixture two` toast. The row returns under `Next Action` and `archivedAt` reads `null` again.
- **Settle advances (`gtd-settle-advance`).** Open `Alpha fixture one` with `agent-browser --session "$RUN" click '[data-gtd-row="<alpha-one-id>"] a[data-sidebar-thread-id]'` and record `get url`. Settle it by the Tab path. The URL changes to the thread of the next row below it in the same shelf, which may sit in the next project group; when the settled row was the shelf's last, it opens the row above instead. Restore `Alpha fixture one` with `"$TB" thread unarchive <alpha-one-id>` before continuing.
- **Command palette settle (`gtd-settle-palette`).** With `Beta fixture one` open, press `Escape` to leave the composer, open bb's command palette with `agent-browser --session "$RUN" press Control+k` (the `palette.open` binding mirrored from live; `"$TB" settings keyboard list --json` shows it), type with `agent-browser --session "$RUN" keyboard type "settle"`, and confirm option `GTD Sidebar: settle thread` is listed beside Vimium's `Settle the focused thread`; press `Enter`. `"$TB" thread show <beta-one-id> --json | jq .thread.archivedAt` prints a timestamp. Restore it with Un-settle. The entry is absent on Home, where no thread is open.
- **Row context menu (`gtd-row-menu`).** Focus `[data-gtd-row="<beta-one-id>"] a[data-sidebar-thread-id]`, run `agent-browser --session "$RUN" press Shift+F10`, then `agent-browser --session "$RUN" snapshot -i -c > "$EV/gtd-row-menu.snapshot.txt"`. A menu named `Thread actions` opens. Its first group is `Settle` and `Snooze until tomorrow`; the rest is bb's thread action registry in bb's order: `Open in split`, `Copy link`, `Pin`, `Mark unread` or `Mark read`, any plugin entries such as `Notifications, All activity` (a submenu), `Rename`, `Regenerate title`, and the destructive `Delete`. There is no `Archive`. Record every item the snapshot lists, then drive each one below; close the menu with `press Escape` between them. A snoozed row's menu leads with `Wake now`, a settled row's with `Un-settle`.
  - **Pin (`gtd-pinned-shelf`).** Choose `agent-browser --session "$RUN" find role menuitem click --name "Pin"`. A `Pinned` region appears above `Next Action` holding `Beta fixture one`; its header is a plain heading with no fold. `"$TB" thread show <beta-one-id> --json | jq .thread.pinnedAt` prints a timestamp. Reopen the menu and choose `Unpin`; the row returns to `Next Action` and `pinnedAt` reads `null`.
  - **Mark unread / Mark read (`gtd-unread`).** Choose `Mark unread`. `agent-browser --session "$RUN" get text '[data-gtd-row="<beta-one-id>"]'` starts with `Unread response`, and the title renders at weight `500`. Choose `Mark read` to restore.
  - **Open in split.** Open `Alpha fixture one`, then choose `Open in split` in `Beta fixture one`'s menu. A second thread pane opens beside the first, each pane header with `Maximize pane` and `Close pane`, and the URL moves to the split thread (`/projects/<beta-id>/threads/<beta-one-id>`). Capture a screenshot, then close the split with the second `Close pane` button from a snapshot; the URL returns to the first thread.
  - **Copy link.** Headless Chrome denies both `navigator.clipboard.readText()` and `agent-browser clipboard read` (`Read permission denied`), so spy on the write instead. Before opening the menu, run `agent-browser --session "$RUN" eval '(() => { window.__copied = []; const c = navigator.clipboard, w = c.writeText.bind(c); c.writeText = (t) => { window.__copied.push(t); return w(t).catch(() => {}); }; return "spy"; })()'`; a reload drops it, so install it after the last `open`. Choose `Copy link`: a `Thread link copied` toast appears and `eval 'JSON.stringify(window.__copied)'` returns `["<URL>/projects/<beta-id>/threads/<beta-one-id>"]`. The spy proves what bb writes, not that the OS clipboard holds it; paste in a headed browser for that.
  - **Rename (`gtd-rename-inline`).** Choose `Rename`. A textbox `Thread name` replaces the title, focused. Run `agent-browser --session "$RUN" press Control+a`, `agent-browser --session "$RUN" keyboard type 'Beta renamed'`, and `agent-browser --session "$RUN" press Enter`. The row reads `Beta renamed` and `"$TB" thread show <beta-one-id> --json | jq -r .thread.title` prints `Beta renamed`. Double-click the row link (`agent-browser --session "$RUN" dblclick '[data-gtd-row="<beta-one-id>"] a[data-sidebar-thread-id]'`) to reopen the editor; `press Escape` keeps the title. Clearing the text and pressing `Enter` shows `Name cannot be empty.` Rename it back to `Beta fixture one`.
  - **Delete.** Spawn a disposable `Beta delete me` thread. Choose `Delete` in its menu, then `agent-browser --session "$RUN" find role button click --name "Delete thread"` in bb's dialog (`Cancel` backs out). The row leaves the list and `"$TB" thread show <delete-id> --json` fails with `thread_not_found`.
  - **Notifications.** Choose `find role menuitem click --name "Notifications"`. A submenu `Notifications` opens with `Same as default`, `All activity`, `Needs input only`, and `Muted`. Choose `Muted`, reopen the row menu: the item reads `Notifications, Muted`. Restore with `Same as default`; it reads `Notifications, All activity` again.
  - **Regenerate title.** Listed on every row. Choosing it asks Codex for a title, a paid call, so do not drive it here. <!-- unverified -->
  - **Section moves.** No section entries appear while bb organizes the sidebar by project (`sidebar.organizationMode` is `project`), so whether moving a pinned thread to a section unpins it is untested. <!-- unverified -->
- **Group Move up / Move down (`gtd-group-reorder`).** With both projects in `Next Action` and alpha first, run `agent-browser --session "$RUN" focus '[data-project-id="<alpha-id>"] button[aria-expanded]'` and `agent-browser --session "$RUN" press Shift+F10`. A menu `verify-alpha project actions` offers only `Move down` (alpha is the top group). Choose `agent-browser --session "$RUN" find role menuitem click --name "Move down"`. The snapshot lists `verify-beta project` before `verify-alpha project` in every shelf, and `"$TB" project list --json` lists verify-beta before verify-alpha. Restore with alpha's `Move up`.
- **Group drag (`gtd-group-reorder`).** Drag the alpha header below the beta header with the pointer: read both header boxes with `eval` on `[data-project-id] button[aria-expanded]`, then `agent-browser --session "$RUN" mouse move <ax> <ay>`, `mouse down`, `mouse move <ax> <ay+12>`, `mouse move <bx> <by+8>`, `mouse up`. With alpha's header at (125, 240) and beta's at (125, 348), moving through y 252, 300, and 356 flips the order as with Move down, the URL stays `/`, and `project list` agrees. Restore with `Move up`.
- **Group new thread (`gtd-group-new-thread`).** Under `(hover: none)` the `+` is always visible. Run `agent-browser --session "$RUN" find role button click --name "New thread in verify-beta"`. The Home composer opens with button `Project: verify-beta` and focus in its prompt; the URL stays `/`. Return without sending.
- **New Captain (`gtd-group-captain`).** Only while the Captain plugin is enabled and running on the instance (`"$TB" plugin list --json`). Run `agent-browser --session "$RUN" find role button click --name "New Captain directing verify-beta"`. A dialog `New Captain` opens with a `Name` textbox, a `Repos` list with `verify-beta` checked, and `Cancel` / `Start Captain`. Choose `Start Captain` with no name: `Name the Captain.` appears. Choose `Cancel`; the dialog closes. Starting a Captain launches a long-lived agent thread, which costs a turn; skip it unless the run is budgeted.
- **Hover card (`gtd-hover-card`).** Reach a row by keyboard so the card opens: focus the row link, `press Shift+Tab`, then `press Tab`. Run `agent-browser --session "$RUN" wait --fn '!!document.querySelector("[role=tooltip]")' --timeout 3000` and `agent-browser --session "$RUN" get text '[role=tooltip]'`. The text has the title, `verify-alpha` (and the branch, if bb knows one), and the provider name. A family parent adds `<n> subthreads`; a child adds `Child of <parent>`. Phones show no card.
- **Status slot (`gtd-status-slot`).** Read every row's slot with one probe; `get text` on the row omits it. The slot is the element the row link's `aria-describedby` names:

  ```bash
  agent-browser --session "$RUN" eval 'document.activeElement.blur(); JSON.stringify([...document.querySelectorAll("[data-gtd-row] a[data-sidebar-thread-id]")].map(a=>{const s=document.getElementById(a.getAttribute("aria-describedby")); return [a.getAttribute("aria-label"), s?.textContent, s?.querySelector("svg")?.getAttribute("data-icon")||null]}))'
  ```

  Blur first: a focused row swaps its slot for the park buttons. Observed states, each from a fake-agent fixture (see Free agent turns in SKILL.md):
  - A `--send-at` fixture: icon `Clock`, empty text (the pending send).
  - A finished fake turn, unread: text `Unread response` with a dot. After `Mark read`, or after opening it: the age, `now`, then `1m`, `9m`.
  - A running turn: icon `Loading`, labelled `Thread working`. Hold the turn open by replacing `$EV/reply.md` with a FIFO (`mkfifo "$EV/reply.md"`) before `thread spawn --provider acp-verify-fake`; release it with `echo done > "$EV/reply.md"`, then put a regular file back.
  - A failed turn: icon `CircleX`, labelled `Unread thread failed`, under `Next Action`. Hold a turn as above, read the fake agent's pid from the session id in `$EV/fake-agent.jsonl` (`fake-<pid>-1`), confirm it with `ps -o cmd -p <pid>` (it runs `fake-agent.mjs`), and `kill <pid>`. Provider Retry, mirrored on, retries only subscription-limit failures, so it leaves this one alone; `thread show … | jq .thread.status` prints `"error"`.
  - A snoozed row on the opened Snoozed shelf: the hours to wake, such as `15h`, beside an alarm glyph.
  - bb's waiting-for-input glyph: the fake agent never asks for approval or input, so this state was not reached. <!-- unverified -->

- **Jump keys (`gtd-keyboard`).** Rows carry no `aria-keyshortcuts`. Read the bindings with `"$TB" settings keyboard list --json | jq -c '.. | objects | select(.command? // "" | test("thread\\.jump"))'`: on Linux web the binding is `mod`+`Shift`+digit, so `Control+Shift+<n>` opens the n-th visible row, counting down the list across groups. Press `Escape`, then `agent-browser --session "$RUN" press Control+Shift+3`: the URL moves to the third row's thread. While both modifiers are held (`agent-browser --session "$RUN" keydown Control`, `keydown Shift`; `keyboard down` does not exist), every row's slot reads its key, `Ctrl + Shift + 1`, `Ctrl + Shift + 2`, …, in the Status slot probe. `Control` alone shows nothing. Release with `keyup Shift` and `keyup Control`; the slots return.
- **Families (`gtd-families`).** Spawn `Alpha parent` and `Alpha child` in alpha with `--send-at "$AT"`, then nest the child: `"$TB" thread update <child-id> --parent-thread <parent-id>`, which prints `Parent: <parent-id>`. The parent row shows button `Expand children of Alpha parent` with `expanded=false`, and the child is hidden.
  - **Fold persists.** Choose that button. The child appears indented under the parent and `"$TB" gtd-sidebar prefs get expandedThreads` lists `<parent-id>`. Reload: the family is still open. Focus the parent link: `press ArrowRight` on a folded parent opens it, and a second `ArrowRight` moves focus to the child link (`eval 'document.activeElement.getAttribute("aria-label")'` returns `"Alpha child"`). `ArrowLeft` on the child moves focus back to the parent; `ArrowLeft` on the open parent folds it.
  - **Spawning a child directly.** `thread spawn --parent-thread <parent-id> --provider acp-verify-fake --title "Alpha child" --prompt …` creates a nested child with one fake turn. ## Gotchas

- Headless Chrome matches `(hover: none)`, so the hover park buttons never appear. `click @ref` on them reports the row's link covering the button, and a pointer press there opens the thread instead. Use the keyboard path above. Verify the hover reveal itself in a headed browser and say which path you drove.
- `[data-gtd-row="<thread-id>"]` is the stable row handle. Row links carry `data-sidebar-thread-id`.
- Settings pages replace the sidebar with Settings navigation, so the GTD list is not visible there. Check sidebar results after returning Home.
- Group headers render only with two or more projects in view. Rows on the Snoozed and Settled shelves count, so parking a project's last row keeps the headers.
- Empty shelves do not render. An absent shelf is not a product gap.
- The test instance starts with no threads, so every shelf needs a fixture. A `Waiting` row needs a thread that is actually running: hold a fake-agent turn open with a FIFO reply file (Waiting shelf step).
- Rows of scheduled threads show a clock in their status slot. That is the pending send, not a snooze.
- gtd-sidebar's thread namer can rewrite a spawned thread's title. Wait for the fixture title before asserting on it, and rename with `"$TB" thread update <id> --title` if it changed.
- bb's archive toast reads `Thread archived <title>` with an `Undo` button; `wait --text "Thread archived"` matches it.
- `"$TB" project delete` also deletes the project's threads.
- Once a project has rows on two shelves, `verify-alpha project` names more than one button. Scope snapshots to `section[aria-label="<Shelf>"]` and click by `@ref`, or the first match may be the wrong shelf.
- Shelf folds and project-group folds are session state: a reload returns to the defaults (Waiting open; SlopCop, Snoozed, and Settled folded; Settled groups folded). Family folds persist through `expandedThreads`.
- `Move up` / `Move down` appear only where a move is possible: never past the edge group, never on the personal project, and never in the compact layout.
- A working row has no park buttons at all, and its menu omits `Snooze until tomorrow` while keeping `Settle`. Whether a working child also removes Snooze from its idle parent's row and menu is untested.
- `"$TB"` drops every `BB_*` variable, so a CLI call never runs as a thread. `rename` needs an explicit thread id; use `scripts/as-thread.sh` to run it as a thread.
- Never run `gtd-sidebar rename <id>` without `--title`, or the menu's `Regenerate title`, on a thread that has had a turn: both ask Codex for a title, a paid call.
- `agent-browser get text` on a row omits its status slot; read the slot through the row link's `aria-describedby` (Status slot step).
- agent-browser holds modifiers with `keydown <key>` / `keyup <key>`; `keyboard down` does not exist.
- Settling a parent archives its children with no confirmation (a `window.confirm` spy records no call). Its row's `Un-settle` restores only the parent; the toast's `Undo` restores the family.
- A textbox setting cannot be cleared from the settings page. Restore it with `"$TB" plugin config <id> unset <key>`.
- On an open thread the composer has focus. Press `Escape` before a keyboard shortcut such as `Control+k`, or the keys type into the composer.
- A mouse hold opens the sheet only in the compact layout; on a wide window it opens the desktop menu. The hold is 200 ms.
- Captain controls (`New Captain directing …`, Captain icons, `need you` counts) render only while bb reports the Captain plugin running on this instance.
- A search query opens every shelf and group, so fold assertions made with a query active are meaningless.
- Pointer drags need more than 8 px of travel before they start; a shorter move is a click and opens the row.
