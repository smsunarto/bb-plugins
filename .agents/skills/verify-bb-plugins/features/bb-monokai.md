# bb Monokai

bb Monokai is a dark-only palette that restyles bb's chrome, code, and diffs from one set of colours, with a UI font setting that switches the app between Inter and SF Pro. It also ships a Monokai code theme for diffs and file previews, a matching terminal, and content scripts that restyle bb's own DOM: search fields, the right panel's new tab, Git diff headers, the New thread screen, the project control, archive toasts, phone thread headers, and the phone right panel's depth and tab motion.

## Sub-features

Each line names the state it needs: none, project, thread, diff, terminal, editor, narrow (a 390px viewport), or unreachable.

- `monokai-palette` selects bb Monokai under Settings → Appearance → Palette. (none)
- `monokai-dark` renders the Monokai grounds, text, and accent in Dark appearance. (none)
- `monokai-active-flag` sets `--bb-monokai-active: 1` under Dark, which switches on the diff header, terminal, and Monaco adapters. (none)
- `monokai-ui-font` switches the app font between `Inter (Default)` and `SF Pro`. (none)
- `monokai-hairline-density` pins `--monokai-device-pixel` to one device pixel. (none)
- `monokai-search-fields` draws bb's search fields as 36px hairline fields. (none)
- `monokai-home-marker` marks the New thread screen, drops its page outline, and hides the plugin's empty homepage section. (none)
- `monokai-new-thread-layout` centres the New thread composer in the pane at desktop widths. (none)
- `monokai-project-control` adds `Clear selected project` to the new-thread project control and renames `Don't work in a project` to `No project`. (project)
- `monokai-thread-marker` marks the page while a thread is open. (thread)
- `monokai-panel-new-tab` opens a thread's right panel on a new tab when the user presses the toggle. (thread)
- `monokai-new-tab-launcher` centres the new tab's Actions as hairline cards and hides its Actions header, reorder handles, and Recent list. (thread)
- `monokai-terminal-appearance` gives terminals Berkeley Mono at 13px, 1.4 line height, on `#181818`. (terminal)
- `monokai-terminal-palette` maps the 16 ANSI colours. (terminal)
- `monokai-diff-header` draws Diffs.com-style file headers with change-kind icons in bb's Git diff view in the right panel and hides Open in editor there. (diff; needs bb's built-in Git plugin, disabled on the mirror)
- `monokai-diff-palette` colours diff additions, deletions, gutters, and the file tree's git-status column. (diff)
- `monokai-code-theme` colours syntax tokens in diffs and file previews from `bb Monokai Code`. (diff or thread)
- `monokai-monaco-syntax` adds function-name colour and bold declarations in bb's Monaco editor. (editor; needs the `monaco-editor` plugin, disabled on the mirror)
- `monokai-thread-header-rows` closes the gap under a phone thread header whose plugin rows are empty. (narrow, thread)
- `monokai-phone-toggle` draws the 44px sidebar-toggle circle on a phone thread header. (narrow, thread)
- `monokai-panel-depth` slides the phone thread aside under a scrim that closes the right panel on a tap. (narrow, thread)
- `monokai-panel-tab-glide` slides the tab pager's highlight between same-size tabs on a pointer switch. (narrow, thread)
- `monokai-panel-tab-haptics` plays a selection haptic as the pager's active tab changes. (unreachable: bb's iOS app only)
- `monokai-plugin-page-inset` runs phone plugin pages under the home indicator. (narrow; not registered by the current build, see Gotchas)
- `monokai-archive-toast` restyles archive confirmations as a single-row `Archived` card with Undo. (thread, consumed)
- `monokai-shell-layout` reshapes bb's shell beyond colour: the inset page and sidebar motion, scroll-edge fades, the phone drawer's depth, drawer-style menus on a phone, toast layout, and agent markdown and code blocks. <!-- unverified: added from a source audit, not driven -->

## How to get to it (user POV)

- Open **Settings → Appearance**, choose **Palette**, then **bb Monokai (monokai)**.
- Open **Settings → Plugins → bb Monokai** and choose **UI font**.
- Run `bb theme set plugin:monokai:bb-monokai` in a terminal.
- Open **New thread** for the home marker, the centred composer, and the project control's clear button.
- Use any search field: Settings' sidebar search, the command palette, a model or branch picker, or the right panel's new tab.
- Open a thread for the thread marker. Press **Show right panel** in its header, or that button's shortcut, to land on a new tab with centred Actions.
- From the new tab, start a **Terminal** for the terminal font and palette.
- Open a diff in the right panel of a thread whose project has uncommitted changes for the diff colours and syntax tokens: bb's Git view (diff headers too) when its built-in Git plugin is enabled, or a file row under **Source Control → Uncommitted changes**. Search a file name on the new tab and open it for a file preview. Open bb's Monaco editor for the editor tokens.
- On a phone, or any window 767px wide or narrower, open a thread and its right panel for the header toggle, panel depth, and tab pager.
- Archive a thread for the archive toast.

## Gotchas

- Light mode keeps bb's default palette. Judge Monokai only after the baseline probe reports `dark: true`.
- A browser session relaunched after a bb restart forgets `set media dark` and the viewport. Run both again, then reopen the page.
- The font saves the moment you pick it; there is no Save button. Wait for the CSS variable, not for a toast.
- The UI font does not change the code font.
- Clicking `UI font` before the settings page renders fails with `none match name "UI font"`. Wait for the text first.
- Content scripts mount a moment after `wait --text` succeeds. A probe run at once can miss `style[data-monokai-bb-dom-styles]` and read bb's unstyled 28px field. Wait with `wait --fn '!!document.querySelector(…)'`; `wait '<style selector>'` times out because a `<style>` is never visible.
- Syntax token colours inside diffs come from the theme's code theme, not CSS. `plugins/monokai/CONTRACT.md` lists what CSS cannot reach; check it before reporting a palette gap.
- `getPropertyValue` on a custom property returns the authored lowercase hex; computed colours return `rgb()` or `rgba()`. Colours built with `color-mix(in oklab, …)`, such as the focus ring and the phone scrim, have no stable string. Assert attributes and opacity for those, and judge the colour from a screenshot.
- The page ground is `#121213` and text is `#ebebec`. Code, diffs, and the terminal sit on `#181818` with `#e3e3dd` text, so the two grounds differ by design.
- The search fields, new-tab launcher, new-thread layout, tab glide, home marker, thread marker, and project control apply under every palette. The diff headers, terminal, and Monaco adapters act only while `--bb-monokai-active` is `1`.
- The mirror, like live, has bb's built-in Git plugin (`bb--git`) and `monaco-editor` disabled. Without them there is no `[data-testid="git-diff-toolbar-layout"]` and no Monaco editor, so the diff-header and Monaco adapters have nothing to decorate. Source Control's inline diffs and the new tab's file preview still show the code theme. Enabling either plugin changes every user's right panel on the same instance.
- `data-monokai-diff-headers` is set on `<html>` on every page, not only when a diff is open.
- The terminal adapter does nothing when bb already renders the `--terminal-*` typography itself. Matching typography with no adapter work is correct, not a gap. It still tags `[data-monokai-terminal-surface]`.
- The headless test browser runs xterm's WebGL renderer: no `.xterm-rows` DOM. In this run, screenshots showed the terminal as plain `#181818` with no glyphs even after output arrived, with the context not lost and a backing canvas not scaled to pixel ratio 2; whether that is a headless artefact or a product fault is not established. Read the colour variables and `"$TB" terminal output`, say which renderer you saw, and report the blank canvas if you see it.
- In the token probe, skip `[data-line-number-content]` spans: the gutter's line `3` is muted grey and comes before the `3` literal.
- A 390px viewport is narrow but not coarse. Check 44px touch targets, swipes, and the bezel with `scripts/phone-shot.ts`, and sub-pixel hairlines with `scripts/webkit-shot.ts`.
- The phone scrim's centre is off-screen, so agent-browser `click` refuses it. Press its visible left strip with `mouse move`/`down`/`up`.
- The tab glide lives about 200ms and needs two same-size tabs and a real pointer event. Install the recorder before the click; a screenshot afterwards shows only the landed state. Each run of the recorder `eval` adds another observer that pushes into the same `window.__glide`, so a second install on the same page reports one entry per observer. Reload the page or expect that count.
- Panel tab haptics play only in bb's iOS app. A `window.bb.native` stub proves only the plugin's call; label it as a mock.
- `data-monokai-plugin-page` is styled by the theme and covered by a unit test, but the current `app.ts` does not register its content script, so the attribute never appears. Report it as a gap, not a failed drive.
- The plugin's homepage section is meant to be invisible. An empty `New thread screen marker` heading in a snapshot is hidden by CSS, not a bug.
- Judge the clear's picker per painted frame, not per mutation. A MutationObserver sees the options a moment before the tag lands in the plugin's next animation frame, which is still before paint.
- `Clear selected project` exists only in the New thread footer while a project is selected, and only after the control finishes loading (`aria-busy` cleared).
- New thread autofocuses the composer. Press `Escape` before keyboard steps, and type into the new tab's search only after clicking its combobox, or the keys go elsewhere.
- The archive toast's visible title comes from a CSS pseudo-element, so `wait --text "Archived"` does not match. Wait on `[data-monokai-archive-toast]` with `wait --fn` and probe before the toast times out. Other toasts are never tagged.
- Settings pages replace the left sidebar with settings navigation. Open threads from Home.
- The new tab's `Review` action may start a review run; this was not tested. Do not press it while driving the launcher.
- Run the archive bullet last. It archives its fixture thread, and `"$TB" project delete` removes both fixture threads.
