# Usage Bar

Usage Bar puts one macOS menu bar item each for Codex and Claude. An item shows the brand mark and the percent left on the account in use, and its menu stacks a card for each account: plan, last reading, routing state, the session, weekly, and per-model weekly limits with reset countdowns and pace, limit-reset credits, and extra usage. It reads Account Pooler's accounts, or, without the pool, the account each CLI is signed in to. Nothing renders in bb's web UI. The bb server reads quota and sends the menu to every connected host, and only a Mac host draws it.

## Sub-features

- `ub-service` runs one background service, `menu-bar`, that reads quota every 15 seconds and sends the menu to each connected host.
- `ub-source-pool` reads quota from Account Pooler (`account-pool` `account.list`) when the pool has accounts.
- `ub-source-builtin` falls back to the `provider-usage.v1` resources of bb's built-in Codex and Claude Code providers on the server's primary host.
- `ub-host-decline` covers non-macOS hosts, which decline to draw. The plugin keeps running and draws nothing there.
- `ub-needs-config` marks the plugin as needing configuration when a Mac lacks the Xcode command line tools or the helper fails to compile.
- `ub-menubar-item` (Mac only) shows one item per provider with the brand mark and the lowest percent left. Its tooltip names the limit, as in `Session 52% left`. With no reading it shows `–`, and the item dims when a refresh fails.
- `ub-account-card` (Mac only) shows a card per account in priority order: identity, plan, `Updated …`, and `In use · N in flight`, `Last used`, `Held · back in …`, `Exhausted`, `Disabled`, or `Refreshing…`.
- `ub-limit-rows` (Mac only) shows `<Label> N% left` rows (Session for Codex only, Weekly, `<Model> weekly`), each with `Resets in …` and a pace line such as `18% in reserve` or `6% in deficit · Runs out in 14h 3m`.
- `ub-reset-credits` (Mac only) shows `N limit resets` with `Next expires in …`, or `Check Claude for full resets`, which opens Claude's usage page.
- `ub-extra-usage` (Mac only) shows `Extra usage <amount> credits` for Codex, or `Extra usage $X left` `of $Y a month` for Claude.
- `ub-menu-actions` (Mac only) provides `Refresh` (⌘R), `Open bb` (⌘O), and `Quit Usage Bar` (⌘Q). Quit hides the items until bb restarts or the plugin reloads.
- `ub-error-banner` (Mac only) shows `Couldn't refresh usage. Showing the last reading.` above the cards when a read fails.
- `ub-single-helper` (Mac only) draws one menu per Mac. When two bb servers reach the same Mac, the first keeps the menu bar.
- `ub-no-settings` declares no plugin settings, CLI command, agent tool, or app UI.
- `ub-claude-web` reads Claude full-reset credits through an installed CodexBar CLI when Claude's OAuth reply omits them. Needs macOS with CodexBar. <!-- unverified: added from a source audit, not driven -->
- `ub-dev-idle` stays idle under a `~/.bb-dev` data directory unless `BB_USAGE_BAR_ANY_INSTANCE=1`.

## How to get to it (user POV)

- Install or enable the plugin. On a Mac that is connected to bb as a host and has the Xcode command line tools, the Codex and Claude items appear in the macOS menu bar. The first start compiles the helper, which can take up to a minute.
- Click a menu bar item to open its account cards and the `Refresh`, `Open bb`, and `Quit Usage Bar` actions.
- **Settings → Plugins → Usage Bar** at `/settings/plugins/usage-bar` shows only `Plugin details`, `Usage Bar`, and the description `Shows session, weekly, and per-model quota, limit reset credits, and extra usage for each Codex and Claude account in the macOS menu bar.`, with no Configuration section.
- The bb web UI has no Usage Bar surface. bb's built-in **Provider usage** settings page (`/settings/plugins/bb--provider-usage`) shows usage limits, but on the test instance it listed only `Account Pooler` with `No accounts report usage yet.`, not the built-in Codex and Claude Code resources, so it cannot cross-check `ub-source-builtin` there. It does not show the bar.

## Driving it with agent-browser

Preconditions:

- The doctor passes with `--plugin usage-bar`; on the test instance it reported the plugin running from the source copy and matching the checkout and build. `"$TB" plugin logs usage-bar -n 50` printed nothing, so the log cannot confirm a reload.
- The test instance runs on this Linux machine, and its only host is Linux. That host answers `unsupported`, so every `(Mac only)` sub-feature is unreachable here. Report each one as unreachable for lack of a Mac host connected to the test server. Do not count a check on the live Mac as proof of the test build.
- Values depend on provider accounts. The test instance does not copy Account Pooler's accounts or secrets, so the pool is expected to be empty, and the fallback reads this machine's own `codex` and Claude Code sign-ins. Percentages, plans, reset credits, and extra usage come from those real accounts. Keep emails out of `$EV`.

- **Service running (`ub-service`, `ub-host-decline`).** Run `"$TB" plugin list --json | jq '.plugins[] | select(.id=="usage-bar") | {enabled, status, statusDetail, services}'`. It prints `"enabled": true`, `"status": "running"`, `"statusDetail": null`, and `"services": [{"name": "menu-bar", "state": "running"}]`. The text form `"$TB" plugin list` prints `usage-bar@0.1.0  running`, its `source: path:…/src/plugins/usage-bar`, and `service menu-bar: running`. Run `"$TB" plugin logs usage-bar -n 50 > "$EV/usage-bar-logs.txt"`: it was empty, so it has no `needs-configuration`, `swiftc`, or `helper exited` line, consistent with a Linux host declining before it builds anything. Nothing observable on the instance shows the decline itself, and the 15-second read cadence was not measured. <!-- unverified: host decline message, 15 s cadence -->
- **No settings (`ub-no-settings`).** Run `"$TB" plugin config usage-bar`. It prints `This plugin declares no settings.`
- **Source selection (`ub-source-pool`, `ub-source-builtin`).** List the usage sources with `"$TB" plugin rpc list --method provider-usage.v1.listResources --json | jq -r '.[].pluginId'`. It printed `account-pool`, `provider-acp`, `provider-claude-code`, and `provider-codex`. Read the pool without identities: `"$TB" plugin rpc call account-pool account.list --json | jq -c '[.[] | {provider, status, enabled}]'`. It printed `[]`, and `"$TB" plugin rpc call account-pool provider-usage.v1.listResources --input-file "$EV/empty.json" --json | jq -c '[.resources[]]'` also printed `[]`. An empty pool means Usage Bar uses the fallback; a non-empty one means it uses the pool. Which source the service actually chose is not exposed, so this is input evidence only. <!-- unverified: the service's own source choice -->
- **Fallback input (`ub-source-builtin`).** Run `printf '{}' > "$EV/empty.json"`, then `"$TB" plugin rpc call provider-codex provider-usage.v1.listResources --input-file "$EV/empty.json" --json | jq -c '[.resources[] | {providerId, scope}]'`. It printed `[{"providerId":"codex","scope":{"kind":"host","hostId":"host_…","hostName":"<host>"}}]`; `provider-claude-code` printed the same with `"providerId":"claude-code"`. Usage Bar keeps only resources whose `providerId` is `codex`, `claude`, or `claude-code`, scoped `shared` or to the server's primary host. To read a resource without identities, write `{"resourceId": <id from listResources>, "refresh": false}` to a file and run `"$TB" plugin rpc call provider-codex provider-usage.v1.getResource --input-file <file> --json | jq -c '{status: .usage.status, windows: [.usage.windows[]? | .label]}'`. Codex printed `{"status":"ok","windows":["Weekly limit"]}`; Claude Code printed `{"status":"unauthenticated","windows":[]}` on this Linux host. The raw output carries `accountKey` and `accountEmail`, so never save it unfiltered.
- **Cross-check in the UI.** Open `agent-browser --session "$RUN" open "$URL/settings/plugins/bb--provider-usage"` and run `agent-browser --session "$RUN" wait --text "Provider usage" --timeout 15000`. (`/settings/plugins/provider-usage` renders `This plugin is not installed.`) The page has `Usage limits`, `Your provider subscription usage.`, and a `Reload usage data` button. On the test instance, even after 12 seconds, it listed only `Account Pooler` with `No accounts report usage yet. Configure accounts in the source plugin’s settings.`; the built-in Codex window did not appear there, so the page did not cross-check the fallback. Where it does list windows, it shows account emails and plans, so save no screenshot of it. Record only window labels and counts in `$EV/result.md`, labelled as input evidence. <!-- unverified: UI cross-check of fallback windows -->
- **Needs configuration (`ub-needs-config`, Mac only).** This needs a Mac host without the Xcode command line tools, connected to the server under test. On such a host, `"$TB" plugin list --json | jq '.plugins[] | select(.id=="usage-bar") | .statusDetail'` names `Host <id>: Usage Bar needs the Xcode command line tools…`. <!-- unverified --> Report it as unreachable on the Linux test instance.
- **Mac-only menu (`ub-menubar-item` through `ub-single-helper`).** These need a Mac host with the Xcode command line tools connected to the bb server under test. On a Mac connected to live, the route is to click the Codex or Claude item in the menu bar, read the cards, press ⌘R, and check that `Refreshing…` appears and then clears. The proof is a `screencapture -x` of the open menu and `bb plugin logs usage-bar` on that server. Do not run Quit or Refresh on live as part of a test-build verification. ## Gotchas

- The web UI has no Usage Bar surface, so a browser screenshot of bb cannot prove the bar. The Provider usage page proves only the input data.
- A data directory under `~/.bb-dev` makes the service idle with `usage-bar: dev bb instances do not draw the menu bar; idling.` The test instance lives under `~/.bb-test`, so this does not apply to it, and no `BB_USAGE_BAR_ANY_INSTANCE` is needed.
- In fallback mode, the test server reads this machine's real credentials: `~/.codex/auth.json` and Claude Code's `~/.claude/.credentials.json`, or the keychain on macOS. It also calls `chatgpt.com` and `api.anthropic.com` for reset credits and extra usage at most every five minutes, even though no host draws the menu. The reads never refresh a token. Expect this traffic, and do not paste token-bearing output into `$EV`.
- The fallback collects quota only from the bb server's primary host. A Mac connected to a remote server shows the server host's CLI accounts, not the Mac's own.
- Pool extras read Account Pooler's private secret files. Without them, the reset-credit and extra-usage rows disappear while quota rows stay. That is the documented behavior, not a product gap.
- Built-in collections, including failures, are cached for five minutes. Only the Mac menu's Refresh bypasses the cache, so a CLI sign-in change on the test host can take up to five minutes to show.
- `getResource` takes `{"resourceId", "refresh"}`, not `{"id"}`; the resource id is a JSON-array string such as `["host_…","codex",…]`, so pass it with `jq -c` rather than by hand.
- On a Linux server host, Claude Code's fallback resource can read `unauthenticated` while Codex reads `ok`, so one provider's item would show `–`. That reflects this host's sign-ins, not a Usage Bar gap.
