# T3 Composer

A fork of BB’s composer styled after the ChatGPT macOS app, with BB’s 12px corner radius: a rounded surface, a 14px/20px editor (16px on touch screens), 28px controls, a `+` menu, the model pill and the permission mode on the left, and a round send button. As in ChatGPT, the project, machine and branch row sits in a full-width tray attached above the surface, and attachments show as tiles above the text, with annotations and comments counted in chips instead of inline pills. BB renders that row and its menus, so the plugin moves and restyles them with CSS keyed to BB’s `data-follow-up-composer-footer` and `data-new-thread-footer` attributes and the Project and Environment menu labels; the menu styling applies wherever BB shows those menus. Colors and the selected font follow the active BB theme. Save draft is a direct icon action beside the attachment and microphone buttons, including in collapsed composers. BB retains its explicit compact/expanded layout selection so model and plugin controls remain available; the renderer does not automatically collapse one-line drafts like ChatGPT.

Install this directory with `bb plugin install .`, then choose **T3 Composer** under **Settings → Appearance → Composer** if Automatic has not selected it. Requires BB 0.49.0 and SDK 0.6.132. To switch back, choose the built-in **Composer** there.

Drafts, uploads, voice input, history, model selection, and sending use BB’s public composer API. Save draft holds the message in BB’s queue until you send it manually. This plugin replaces their presentation in thread, new-thread, queued-message, and sent-message composers. It retains BB’s prompt-action menu and shows other plugins’ composer actions, including BB’s overflow menu, after the permission mode; compact composers omit them as BB’s composer does. Alternate send actions remain available with a hardware keyboard. The removed send-options menu and long-press sheet are not available on touch-only devices. Save draft follows the built-in Drafts plugin’s scope and availability, so Drafts must be enabled. BB excludes queued-message and sent-message editors.

New-thread project choices leave out the projects Captains live in. The composer reads them from the Captain plugin's `homeProjects` RPC, which refreshes when a Captain starts or is archived, and caches the last answer in localStorage per origin so a page load applies it at once; a failed read keeps the cache, and without Captain nothing is hidden. A new-thread composer that lands on one of those projects, whether remembered by BB, opened from its route, or picked by hand, moves through `setSelection` to the last other project this window used, or to "No project", retrying while BB refuses the change mid-upload. BB's project picker has no plugin hook to filter its list, so a content script (`src/captain-projects/project-picker-hide.ts`) hides the rows in BB's DOM, in the new-thread picker only; other project pickers, such as Settings → Archived threads, still list Captains. It depends on BB's ProjectSelector markup: the new-thread footer's `[data-promptbox-project-control]` button with `aria-expanded` and, on desktop, `aria-controls`; the popover in a Radix popper wrapper and, on phones, a persistent drawer on `<body>`; a cmdk list inside an element labelled `Project`, with the project id in each `[cmdk-item]`'s `data-value`; and cmdk skipping `aria-disabled="true"` rows and handling Home. If BB changes that markup, the rows show again and the fallback still keeps new threads out.

Upstream is BB's `plugins/composer` in get-bb/bb, synced through 2d04779a1 (#7635, 2026-11-16). The thread composer uses BB's built-in `/handoff` (#7480). #7133 raised dependency ranges for security fixes; at the versions this workspace's lockfile resolves, `bun audit` reports none of this plugin's runtime dependencies.
