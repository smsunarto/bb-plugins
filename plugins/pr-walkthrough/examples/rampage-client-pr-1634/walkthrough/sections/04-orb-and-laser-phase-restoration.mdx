## Guide

### Foundations and data structures

Start with the data that must survive asynchronous event handling and pool waits: phase origin, duration, explicit elapsed time, and the scoped clock dependency. These fields replace implicit local creation time. The invariant is that pooled presentation may be delayed, but its initial phase must still derive from authoritative active time rather than queue latency.

### Core behavior

Follow restoration before steady-state motion. First convert origin tick to elapsed active seconds at spawn, then see how shared orb and laser kernels continue from that restored state, and finally remove the obsolete generic-projectile orb path. Reviewers should verify single application of delivery delay, pause exclusion after instantiation, and one clear owner for each presentation algorithm.

#### Restore the orb angle before its first visible frame

When a pooled orb is ready, the controller asks the server clock for active elapsed seconds since the phase origin, optionally capped by lifetime. It advances the initial angle once by that duration before handing parameters to the orb. Thereafter the orb advances angle and computes XZ position with the shared kernel around the current smoothed owner center.

This two-stage design handles both sources of motion correctly: server time determines where the orbit should begin, while the live smoothed center keeps the visual attached to an interpolated player without restarting the phase.

#### Restore and advance the laser sweep on active time

Immediately before the main-thread spawn, the controller converts phase-origin tick to pause-aware elapsed seconds and passes that value through the pool API. The laser then accumulates `Time.deltaTime` only while gameplay is not paused. Both the static endpoint calculation and moving ping-pong sweep use `LaserSweepKinematics`, removing duplicated angle normalization and traversal math from Unity.

The clock restores delay that occurred before instantiation; the local accumulator handles frames after instantiation. Keeping that handoff explicit avoids double-counting delivery time and avoids advancing through a later gameplay pause.
