For a registered Rampage checkout, hold its slot lease before claiming an Editor or editing the checkout. Create warm slots once from a clean, stopped registered master using game_studio_slots create, sourceSlotId and an absolute destination on the same CoW filesystem. Do not touch the master while it is seeding. Select the Rampage Unity slot BB provider with empty inputs for automatic allocation, or explicit slotId for an adopted Project Checkout environment. Keep the lease across idle, errors and Editor restarts. For handoff, finish and release every Editor claim, close Unity and its MPPM clients while preserving dirty scenes, then release the slot. Stop using the checkout after release. Once all work in a linked Git worktree or BB worktree environment has merged into the target branch, remove it: bb environment delete ID for a BB environment, otherwise git worktree remove PATH then git worktree prune. Stale worktrees still descend from GitButler workspace commits, so they break but pull, and a failed but unapply can overwrite their files. Prove the merge by PR state or patch or tree comparison, not commit subjects; squash merges change SHAs. Keep the branch unless it is also merged and unneeded. First check uncommitted and untracked files: discard Unity or editor drift (Content.asset, Packages/manifest.json, packages-lock.json, ProjectSettings/); commit, preserve or ask about anything else. Never remove a worktree another active thread or agent uses; check BB thread and environment ownership and recent activity. Quarantine requires explicit recovery with observed completion evidence. Direct filesystem/CLI/UI access and BB's Send-now, edited-message resend and manual compaction remain cooperative boundaries.
