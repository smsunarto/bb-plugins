Manage persistent Rampage client checkout slots. Register a stopped master checkout with its BB project and host. Create warm slots from sourceSlotId into an absolute path on the same copy-on-write filesystem, optionally choosing a new scott/ branch. Creation requires a clean, stopped master with a populated Library and locally hydrated Git LFS objects. It freezes the source lease, creates independent Git metadata, and natively copy-on-write clones the cache without Pipeline credentials or MPPM clones. Unsupported CoW fails without a full-copy fallback. Completed retries preserve existing work; partial failures stay fenced for inspection. Select the unity-rampage-slot BB provider with empty inputs to reserve an available warm slot, or explicit slotId for an adopted Project Checkout environment. Acquire a lease from a thread in that checkout, then claim its exact Unity Editor with game_studio_manage. Slots retain their Library cache and GitButler state across tasks. List exposes lease IDs only to their owner. Release requires Editor claims released, all Editors closed and other agents stopped. Failed verification quarantines the slot. Recovery requires explicit completion evidence and confirmation; another caller needs an archived/deleted owner. Retirement preserves all checkout files. No automatic expiry, takeover, branch reset, stashing or deletion.
