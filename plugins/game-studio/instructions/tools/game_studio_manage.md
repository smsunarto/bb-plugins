Coordinate Unity Editor ownership between BB threads on the thread's enrolled host. Actions: list (Editors, claims and reservations per checkout), claim (an exact instance, runtime or authoring), wait (block until it is claimable, then claim), reserve (hold a checkout before `unity open` so the new Editor is yours from discovery), request (ask the owning thread for a handoff), status (native idle state as background.quiet), release, recover (dead Editor, or archived/deleted owner with evidence) and reconcile (pre-upgrade jobs). Runtime claims coexist and allow read-only inspection, including MPPM clients; an authoring claim excludes every other thread on the shared checkout and is required for Assets/Packages writes and scenario lifecycle; clones cannot author. Claims and reservations release automatically when the owning thread's turn ends, once the Editor is quiet, unless hold is true. Conflicts name the owner and its state. A claimId alone identifies its instance. Run Editor operations through the Unity CLI, never through this tool. Supply hostId only to select another enrolled host.
