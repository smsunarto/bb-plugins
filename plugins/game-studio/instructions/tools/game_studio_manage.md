Coordinate Unity Editor ownership between BB threads on the thread's enrolled host. Actions: list (Editors, claims and reservations per checkout), peek (any Editor's idle state and public owner, no claim), claim (an exact instance, runtime or authoring), wait (block until it is claimable, then claim), reserve (hold a checkout before `unity open` so the new Editor is yours from discovery), request (ask whoever blocks you, by instanceId or workspacePath, for a handoff), status (native idle state as background.quiet), release, recover (dead Editor, archived/deleted owner with evidence, or an orphaned reservation by workspacePath) and reconcile (pre-upgrade jobs). Runtime claims coexist and allow read-only inspection, including MPPM clients; an authoring claim excludes every other thread on the shared checkout and is required for Assets/Packages writes and scenario lifecycle; clones cannot author. Claims and reservations release automatically when the owning thread's turn ends, once the Editor is quiet and neither in Play mode nor holding unsaved scenes, unless hold is true. Conflicts name the owner and its state. A claimId alone identifies its instance. Run Editor operations through the Unity CLI, never through this tool. Supply hostId only to select another enrolled host.
