# Filing and attachments

Use this reference only when filing an issue or updating its attachments is authorized.
Prepare the exact body in a file and pass it to the available GitHub tool or authenticated
CLI. With `gh`, inspect the installed command's help for supported options and use
`--body-file` for multiline text. Do not assume attachment support or upgrade the user's
CLI merely because an example used a different release.

When attachments are needed, use a supported upload tool or the authorized browser route
under the session's browser policy. If no available route works, deliver the draft and
validated media with the limitation. Stop after an upload permission denial.

Read an existing issue body before modifying it. Preserve unrelated content and footer
markers. Read back the created or edited issue, confirm attachments resolve, and verify
that media renders. A partially successful command can have already changed the issue:
inspect remote state before retrying to avoid duplicate issues or attachments.

Return the issue URL and identify any incomplete attachment. Do not silently claim a
text-only issue includes the requested visual evidence.
