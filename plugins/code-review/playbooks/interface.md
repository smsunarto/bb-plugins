# Interface

Can users understand and complete the affected task? Suggestions to investigate:

- Entry points, primary actions, navigation, and whether feedback matches the operation's actual state.
- Empty, loading, error, success, and narrow-width states where they exist.
- Recovery from failure, duplicate submissions, and preservation of user input.
- Keyboard access, focus order and restoration, accessible names, contrast, and reduced motion.
- Grouping, hierarchy, typography, spacing, color meaning, and copy that makes the next action clear.

Respect the user's product direction and the project's design system. Explain an observable obstacle to completing the task rather than treating a style preference as a defect.

Use supplied rendered-state evidence when visual or interactive behavior matters. Source inspection alone does not establish how an interface renders or responds. Name states and interactions missing from the evidence as verification gaps.
