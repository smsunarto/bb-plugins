## Findings considered and not planned

- **Wide layout reflows the whole document when a comment opens**
  (`app.css:449-450` adds a 300px column when `data-open`, `app.css:1126-1128`
  removes it while `data-expanded="false"`; `review.tsx:317` sets `data-expanded`
  from `activeId`). Code-confirmed, not recorded (the parent's wide capture was a
  ~710px pane, still overlay mode). Fixing it is a layout decision (reserve the
  column whenever review is open, or overlay at every width), not a motion edit.
  Owner to decide; see the audit summary in the thread.
- **Reduced motion is an instant swap with no opacity feedback**
  (`comment-margin.tsx:36`). The playbook prefers a short crossfade, but the parent
  thread recorded "reduced-motion instant" as settled. Not re-litigated.
- **Selection popover appears instantly** (`selection-actions.tsx`, no transition).
  Appears on every text selection; high frequency, instant is correct.
- **Floating × sits above the card's top-right corner, outside the card**
  (`app.css:1030-1040`). Visual, not motion; it also means the animated surface in
  the overlay layout is 28px taller than the card. Noted for the owner.
- **Layout effect re-subscribes observers on every render** because `items` is a
  new array each render (`comment-margin.tsx:190`, `review.tsx:369`). Churn, not
  motion; no dropped frames observed in the recording.
